研究

Stellex

基于 NeoForge 21.1.x 的加载器发行版（fork + 安装器 + 服务端包）：内置可调 CPU 调度与客户端渲染剔除。附带论文与三组实测数据。

它做什么

Stellex Loader 以 NeoForge 21.1.x 源码为基线构建：加载器内集成 CPU 调度器（按配置百分比驱动真实后台工作，默认是玩家周围的区块异步预生成）与客户端两路渲染剔除（实体、方块实体），并提供图形安装器与服务端包。核心实现最初以模组形态验证，现已并入加载器。

论文

《Stellex：NeoForge 21.1.x 生态下的可调 CPU 调度核心与客户端渲染剔除》，正文约 1.5 万汉字，包含形态论证、系统设计、实现细节、兼容性验证与三组实测数据。

阅读论文全文 →

实测结论摘要

  • 调度器在几乎不影响 tick 的前提下稳定驱动预生成：观测区间内 tick 中位数低于 8 毫秒，最坏 41.6 毫秒，仍维持 20 TPS。
  • 进程 CPU 占用稳定在 34%–62%，并不会无限逼近设定的 80/90 目标——上限由原版区块生成执行器的并行度决定。
  • 因此论文把"目标百分比"表述为闭环上限，而不是硬性承诺。

发行形态

  • Stellex Loader（NeoForge 21.1.x fork，Minecraft 1.21.1 / JDK 21）：图形安装器 stellex-loader-installer.jar + 服务端包 stellex-loader-1.0.0-server.zip，安装器负责下载并解包服务端
  • 模组形态（NeoForge 21.1.x 与 Forge 1.20.1 两个分支）：stellex-neoforge-21.1.251-1.0.0-<构建号>.jar、stellex-forge-47.4.29-1.0.0-<构建号>.jar

两种形态共享同一套调度器与剔除实现：可调 CPU 调度器、客户端两路渲染剔除、不注册自定义网络通道、客户端 Mixin 只在客户端加载。加载器形态在此基础上提供了免手动配置的安装与服务端分发。
