架构说明

Stellex Core 架构说明

模块划分

工程只有一个 Gradle 子项目，源码按职责分为三块：

  • com.mornfire.stellex：入口 StellexCore，只把 NeoForge 事件接到具体模块上，不含业务逻辑。
  • com.mornfire.stellex.governor：服务端 CPU 调度器，只在逻辑服务端生效。
  • com.mornfire.stellex.client 与 com.mornfire.stellex.mixin.client：客户端渲染优化与 Mixin 注入，只在客户端加载。

资源侧只有 META-INF/neoforge.mods.toml、stellex.mixins.json 和语言文件，没有网络通道注册，没有 RegisterPayloadHandlersEvent，没有自定义 CustomPacketPayload。

服务端调度器

线程模型

调度器由四类线程协作：

  • 服务端主线程：ServerTickEvent.Pre 记录 tick 起点，ServerTickEvent.Post 计算真实 tick 耗时、采样 CPU、决定这一 tick 是否还能登记新区块，并调用 addRegionTicket。所有触碰区块管理器与票据管理器的操作都在主线程完成。
  • Stellex 工作线程池：数量由 stellex.cpu.threads 决定，优先级比普通线程低一级。它们从就绪队列取区块坐标，向区块系统请求 ChunkStatus.FULL 的 future 并等待完成，不直接修改世界数据。
  • Minecraft 区块系统执行器：真正的区块生成发生在这里，是 CPU 的主要消耗方，Stellex 不替换也不放大它。
  • 单独的采样节拍：CPU 采样每 500 毫秒最多一次，避免把 getProcessCpuLoad 变成热点。

数据流

  1. ChunkPrefetchPlanner 在主线程按玩家所在区块展开方形半径，去重、剔除已加载与已处理的坐标，按到最近玩家的距离排序，得到候选队列。
  2. 主线程在 tick 仍有空闲预算时，从候选队列取少量坐标，登记 stellex_prefetch 票据（等级为 ChunkLevel.byStatus(ChunkStatus.FULL)），把坐标放进并发就绪队列。
  3. 工作线程取出坐标，在非主线程请求 getChunkFuture(x, z, ChunkStatus.FULL, true)。非主线程请求会被区块系统调度到主线程执行，工作线程只负责等待，因此不会阻塞 tick。
  4. future 完成后，工作线程把坐标标记为已完成，并通过 server.execute 把票据移除排到主线程队列；票据一移除，区块就回到正常的卸载与存盘流程。
  5. 失败或超时的坐标从"已调度"集合里移除，允许下一轮重新排队。

闭环控制

allowedInFlight 是调速的核心变量：CPU 低于目标 5 个百分点以上就增大，高于目标 3 个百分点以上就缩小；平均 tick 超过保护线时直接减半并停止投喂。采样不可用的 JVM 上退化为固定上限，不会因为读不到指标就失控。

不白占的保证

队列排空后工作线程进入 25 到 50 毫秒的休眠循环，不执行任何计算；没有玩家在线时调度器直接返回，只有在显式配置了 -Dstellex.pregen.anchor 固定锚点时才继续以该坐标为中心预生成；暂停状态下只允许在途任务收尾。调度器不会自己"制造"计算量，所有 CPU 消耗都对应一个真实的区块 future。

客户端优化

客户端模块只做两件事，都通过 Mixin 挂在渲染热路径上：

  • EntityRenderer#shouldRender 的 HEAD 注入：距离超过阈值的实体直接判定不可见，跳过后续的包围盒与视锥计算。
  • LevelRenderer#renderLevel 中 BlockEntityRenderDispatcher#render 调用点的 @Redirect：距离超过阈值的方块实体跳过渲染，准星指向的方块实体除外。

两个注入点都先判断总开关与阈值，再判断实体属性，最后才计数；统计计数使用 AtomicLong，每帧只做一次自增，不分配对象。配置在首次 tick 时惰性加载，读取失败时使用默认值并记录日志，不影响启动。

兼容性设计

Stellex 把"兼容"理解为"不改变别人依赖的东西"：

  • 不替换 net.neoforged 与 net.minecraft 的任何类，因此其他模组的 Mixin 目标不会偏移。
  • 不注册必需通道，因此任意一侧缺失都不会导致连接被拒。
  • 不改模组元数据格式与加载顺序，Connector 转译 Fabric 模组时看到的仍是标准 NeoForge 环境。
  • 客户端 Mixin 放在独立的 client 数组，专用服务端加载时根本不会解析它们。
