Fix sodium ShaderLoader

NeoForge 1.21.1 · 修复补丁 · 1.0.0

Sodium 在 NeoForge 上让 nvidium 和 voxy 加载不了着色器，这个补丁先把问题解决掉。修法已经提了上游 PR。

解决 nvidium / voxy 在 NeoForge 版 Sodium 下无法加载着色器的问题。

为什么做它

Sodium 在 NeoForge 上的移植版本有一处着色器加载路径没有对齐：nvidium 和 voxy 依赖的那部分接口在初始化时找不到预期的上下文，结果就是光影加载失败——不是崩溃，而是静默地退回默认渲染。

这个问题在官方仓库里已经有人提过，修复 PR 也提交了，但在合并之前，服务器和整合包需要一个能用的临时方案。

它是怎么运作的

思路很小：不去改 Sodium 本体，而是用一个独立模组在初始化阶段把缺失的上下文补上，让 nvidium / voxy 的着色器加载流程能正常走完。

具体做法：

  • 在 Sodium 的加载阶段注入一段修正逻辑
  • 只针对受影响的加载路径，不改变其他渲染行为
  • 修复思路与提交给上游的 PR 一致，等官方合并后这个模组就可以退役

代码量很小，几乎不增加运行时开销。

怎么用

装进 mods 即可，无前置（但你需要已经装了 Sodium、nvidium 或 voxy 才会用到它）。加载顺序建议放在 Sodium 之后。

如果官方版本已经修复，请删掉这个模组——重复注入没有意义，还可能和新版本冲突。

取舍与边界

不做通用修复。只针对这一处着色器加载问题，不处理其他 Sodium 兼容性问题。

不捆绑 Sodium。模组本身不含 Sodium 代码，只做加载路径修补。

临时方案。上游合并后即弃用，不追求长期维护。

版本与依赖

当前 1.0.0。NeoForge 1.21.1 / Java 21，无强制前置，MIT 协议。适用于 Sodium 在 NeoForge 的对应版本；Sodium 大版本更新后需要确认注入点是否仍然存在。

适用场景与排查

出现下面这些症状时可以考虑装它：

  • 装了 Sodium（NeoForge 版）与 nvidium/voxy，光影设置无效
  • 日志里没有崩溃，但渲染退回默认、帧率异常
  • 换回原版渲染器就正常

装之前先确认三件事：Sodium 的版本、nvidium/voxy 的版本、以及是否已经有官方修复。三者任一不匹配，都可能让这个补丁失效。

升级与退役

这个模组的生命周期跟着上游走。Sodium 官方合并修复后，继续装它没有意义，甚至可能因为注入点不存在而报错。判断方式很简单：删掉它，如果光影能正常加载，就不再需要。

它的存在本身也说明一件事：在模组生态里，"等上游"往往意味着几周的空白期，一个几十行的补丁就能让服务器正常运转——这类小工具值得单独维护。

一个小补丁的价值

这类补丁通常只有几十行代码，却能让一整套渲染方案正常工作。它的维护成本也很低：注入点只有一个，上游合并后直接归档。

如果你在维护整合包，建议把这类"上游未合并的修复"单独列一个清单，定期检查是否已经被官方覆盖。否则整合包里会越堆越多过时的补丁，反而增加排查难度。

为什么单独发一个模组

把这几十行放进整合包的自定义模组里当然也行，但那样只有这个整合包受益。单独发布的好处是别人也能用，坏处是要跟着上游版本走。

我的处理方式是：只在确认问题复现、且上游尚未合并时发布；一旦官方修复，就在说明里标注"建议卸载"。

反馈方式

如果装了之后光影仍然不加载，请附上 Sodium 版本、nvidium/voxy 版本、以及启动日志里与渲染相关的段落。只有"我装了没用"这类信息，没法判断是注入失败还是上游已经改过。

补充一句：这类加载器问题往往只在特定组合下复现（Sodium 版本 + 光影包 + 显卡驱动），所以报告时把三者都带上，能省掉很多来回确认。
