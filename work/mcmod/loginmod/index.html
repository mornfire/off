Login Mod

NeoForge 1.21.1 服务端 · 1.0.0

服务端的登录注册。没登录之前人被冻住、看不见、点不了东西，安安静静把密码输完。

服务端的登录注册。

为什么做它

离线模式服务器（盗版服、内网服）没有 Mojang 的身份校验，任何人输入一个名字就能冒充别人。常规做法是装 AuthMe 之类的插件，但如果服务器是纯 Forge/NeoForge、没有装插件端，就需要一个模组级的方案。

Login Mod 就是这样一个最小实现：注册、登录、未登录时的冻结。

它是怎么运作的

注册：新玩家第一次进服，用 /reg <密码> <确认密码> 注册。密码经过哈希后存进服务端的账户文件，不存明文。

登录：之后每次进服，用 /login <密码> 登录。

未登录状态：玩家会被冻结在当前坐标，附加失明与无敌效果，并且无法：

  • 发送聊天
  • 执行大部分指令
  • 破坏/放置方块
  • 攻击实体
  • 拾取物品

这些限制都在服务端事件层拦截，客户端即使装了修改模组也绕不过去。

登录成功后才解除冻结。如果玩家在未登录状态退出，下次进来仍然要重新登录。

怎么用

服务端必装，客户端可选。首次启动会生成账户数据文件，建议：

  • 把账户文件和服务器存档一起备份
  • 给管理员留一个重置密码的指令（或直接手动改文件）
  • 如果服务器有多个子服，账户文件需要共享或同步

不建议和 AuthMe 等插件同时使用——两套冻结逻辑会互相打架。

取舍与边界

不做验证码/邮箱。这是内网/小服方案，不面向公网大规模注册。

不做会话保持。每次进服都要登录，没有"记住我"。这降低了便利性，但符合离线服的安全模型。

不做权限分级。没有"VIP 免登录"之类的设定，所有人一视同仁。

版本与依赖

当前 1.0.0。NeoForge 1.21.1 服务端 / Java 21，无前置，MIT 协议。账户数据以 JSON 存储，字段包含用户名、盐、哈希与注册时间；升级版本时会保留旧数据。

安全细节

密码不会以明文存储：注册时生成随机盐，用哈希函数处理后写入账户文件。登录时用同样的盐计算并比对。这意味着即使账户文件泄露，也无法直接得到密码。

但这套方案不是"零信任"级别的：没有速率限制、没有二次验证、没有 IP 绑定。它的定位是内网/小服的"防冒名"，不是公网级别的账户系统。如果需要更强的安全性，请用专门的认证插件。

建议的运维习惯：

  • 账户文件和存档一起备份，两者版本要匹配
  • 定期检查账户文件里是否有异常用户名
  • 管理员重置密码走手动改文件，不要在游戏内提供后门指令

常见问题

玩家卡在"冻结"状态通常是登录流程被打断：客户端在登录前掉线、或者服务器在冻结期间重启。重新进服会重新走一遍登录流程，一般能恢复。

如果玩家忘记密码，只能由管理员重置。没有"找回密码"功能——离线服没有可信的联系方式，做找回反而会成为漏洞。

和正版验证的关系

这个模组只适用于离线模式服务器。如果服务器开了正版验证（online-mode=true），玩家身份由 Mojang 校验，再叠一层登录就是多余的操作。

反过来说，如果服务器是正版验证 + 白名单，也不需要它。它的存在场景很明确：没有正版验证、又想挡住冒名登录的内网服。

冻结期间的交互细节

冻结状态下玩家仍然能看到世界、能移动视角，但不能移动位置。这样设计是为了避免"黑屏等待"的不适感——玩家知道自己被拦住了，界面也给出了提示，只是暂时不能行动。

如果不喜欢这种处理，可以改配置关掉失明效果，但冻结与禁令必须保留，否则整个登录机制就形同虚设。
