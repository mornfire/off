OreGuard

NeoForge 1.21.1 服务端 · 1.0.0

反矿透，纯服务端，客户端什么都不用装。除了藏矿，还会看挖掘行为有没有不对劲。

反矿透，纯服务端，客户端什么都不用装。

为什么做它

矿透（X-Ray）是服务器上最常见也最难根治的作弊：客户端装个材质包或模组，把石头变透明，矿物一览无余。传统反矿透靠"伪装方块"——把远处的矿物发给客户端时替换成石头，等玩家靠近再还原。

OreGuard 做的就是这件事，但加了一层：除了藏矿，还看挖掘行为。

它是怎么运作的

纯服务端：不添加任何方块、物品、数据包或注册表条目，客户端不需要安装，也不会因为装了模组而被服务器拒绝。

反矿透层：按玩家视野与距离，动态决定哪些矿物方块对客户端"看起来是石头"。玩家挖到近处时才还原成真实矿物，避免"挖到一半变回来"的突兀感。

行为检测层：统计玩家的挖掘模式——比如垂直往下挖的直线比例、挖到矿的命中率、单位时间内的矿物获取量。异常值会被记录，供管理员判断。

两层是独立的：藏矿解决"看见"，行为检测解决"已经挖了"。

怎么用

只装服务端。默认配置即可工作，建议：

  • 先在测试服跑几天，看误报率（有些玩家就是喜欢直着挖）
  • 行为检测的阈值可以在配置里调，别一上来就设得太敏感
  • 如果服务器有"矿工"玩法（比如挖矿比赛），记得给对应维度关掉反矿透

取舍与边界

不做自动封禁。检测只记录、不处罚，封禁交给管理员。自动封禁的误杀成本太高。

不做客户端校验。不检查客户端模组列表，那是客户端的事，服务端做不了也不该做。

对性能有轻微影响。每个玩家的视野都要计算一次替换逻辑，玩家数很多时需要注意；当前版本按区块批量处理，开销可控。

版本与依赖

当前 1.0.0。NeoForge 1.21.1 服务端 / Java 21，无前置，MIT 协议。不修改世界数据，卸载后已替换的方块会自动恢复为真实状态。

误报与调优

行为检测最容易误伤的是"正常但看起来像作弊"的玩法：

  • 直井挖矿（玩家就是喜欢垂直往下挖）
  • 在矿洞里长时间只挖矿石、不挖石头
  • 用爆炸物快速清矿

上线初期建议只记录、不处罚，观察一周的分布，再决定阈值。不同维度的矿石密度不一样，按维度分别设置比全局统一更合理。

性能与部署

反矿透的计算发生在区块发送给玩家之前，玩家数量多时是主要开销。当前实现按区块批量处理，单人大约在可忽略的量级；几十人同时在线的服务器建议观察 TPS，必要时只对特定维度开启。

部署时注意：反矿透会让客户端看到的方块与真实世界不一致，某些依赖客户端方块数据的模组（小地图、区块扫描类）可能显示异常。这是预期行为，不是 bug。

和客户端反作弊的关系

客户端反作弊（如各种反矿透材质包检测）防的是"装了作弊的客户端"，服务端反矿透防的是"作弊客户端能看到什么"。两者角度不同，不能互相替代。

这个模组不检查客户端，也不发送额外探测包，所以不会和客户端反作弊冲突；但它也挡不住"玩家用另一台设备看地图"这类场外作弊。

什么时候该关掉

如果服务器主打"挖矿竞速"或"资源采集"玩法，反矿透会直接和玩法冲突——玩家本来就该看到矿物。这种情况下按维度关掉是最省事的做法。

另外，开发测试阶段建议关掉，否则调试世界生成时会看到被替换的假方块，容易误判。
