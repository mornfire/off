Soulbound Blades 缚魂之刃

NeoForge 1.21.1 · 1.1.0

二十把剑，每把都得先解谜、再试炼，最后才长成它该有的样子。数值和文案都写在 JSON 里，改起来不用重开游戏。

二十把剑，每把都得先解谜、再试炼，最后才长成它该有的样子。

为什么做它

大部分武器模组的节奏是：挖矿、合成、换上、继续挖矿。剑只是数值的容器，玩家的记忆里不会留下"我当初怎么拿到这把剑"。

缚魂之刃想反着来：先给玩家一个谜面，再给一个必须完成的试炼，最后才让武器进化。拿到剑的那一刻不是结束，而是开始。二十把剑对应二十条路线，每条路线都有独立的叙事碎片。

它是怎么运作的

整套系统分四个阶段：

  1. 获得：通过谜语或线索找到剑的初始形态
  2. 试炼：按剑的要求完成特定行为（击杀、探索、收集、在特定条件下生存）
  3. 进化：试炼完成后剑会成长，属性、外观、Lore 一并变化
  4. 成型：最终形态解锁专属效果

关键在于数据驱动：武器数值、Lore 文本、试炼条件、进化链全部写在 JSON 里，游戏内 /reload 即可热更新。这意味着服务器可以自己改数值和文案，不用重新构建模组；也意味着调试时改一行 JSON 就能立刻验证，不必反复打包。

怎么用

装进 mods 即可，无前置依赖。开局不会直接给剑，需要按线索在世界里找。服务器建议：

  • 把试炼条件调成符合自己玩法节奏的难度（JSON 里改）
  • 如果开了死亡掉落，注意剑的"缚魂"属性是否需要配置保留
  • 用 /reload 改完配置后让玩家重新登录一次，确保客户端拿到新的 Lore

取舍与边界

不做随机掉落。剑不会从怪物身上掉出来，必须走完流程。这让获取曲线可控，也避免了"欧皇一把出、非酋刷一天"的问题。

不做数值怪。二十把剑的强度上限刻意压在合理区间内，最终形态强，但不会强到让其他武器失去意义。

文本量很大。每条试炼都有独立的谜语和 Lore，这部分没法靠程序生成，只能一句句写，所以更新节奏会比纯数值模组慢。

另外配了一个 Lore 补丁（Soulbound Lore Patch），用来修正早期版本里描述与实际效果不一致的地方，两件一起装体验最完整。

版本与依赖

当前 1.1.0（Lore 补丁 1.1.0）。NeoForge 1.21.1 / Java 21，无前置，MIT 协议。JSON 热更新依赖原版 reload 监听，不修改存档结构，卸载后物品会保留但失去试炼进度。

试炼是怎么设计的

每把剑的试炼都遵循同一个结构：先给一个可以观察到的现象，再给一个需要付出的行动，最后给一个不可逆的结果。比如某把剑要求你在雷雨天站在高处被雷劈中——现象是天气，行动是站位，结果是剑进化。

难度是分层的。前几把剑的试炼几分钟能完成，中段需要跑图或准备材料，后段会要求你在危险环境里完成特定行为。没有"限时失败"，做不完可以下次再来，进度不会丢。这一点是刻意的：试炼的意义是让玩家记住过程，不是制造焦虑。

数据驱动带来的维护方式

因为数值、Lore、试炼条件都写在 JSON 里，服务器的调整流程很短：改文件 → /reload → 让玩家重进一次。不需要重新构建，也不需要重启服务器。

但这也带来一个责任：JSON 里的 ID 写错不会报错，只会静默不生效。建议改完之后先用一把测试剑跑一遍完整流程，确认试炼能触发、进化能结算、Lore 能显示。

配套的 Lore 补丁主要修的是文案与效果不一致的地方。它不改变玩法，只改描述——如果你只想要原版体验，可以只装本体。
