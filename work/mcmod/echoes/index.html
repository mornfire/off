Echoes of the Unbound · 未缚回响

NeoForge 1.21.1 · 1.0.0

五个破碎的维度，四个同行的人。故事从告别开始，每次有人死去，镜头都会停一下。

五个破碎的维度，四个同行的人，一条以告别写成的主线。

为什么做它

维度模组通常只有"更多方块、更多怪物"。真正让人记住一个维度的，往往是那里发生过什么。未缚回响的起点是一个很朴素的念头：如果每次穿越维度都要付出一次告别，这个世界会变成什么样。

于是有了五个破碎的维度、四个同行者，和一条从第一句台词就指向结局的主线。

它是怎么运作的

结构上分三层：

  • 维度层：五个破碎维度，各自有不同的环境规则与视觉基调
  • 角色层：四个同行者，各有立场、各自的死亡方式与对应的剧情节点
  • 叙事层：主线按"相遇—同行—告别"推进，玩家的行为会改变某些节点的呈现顺序

每次死亡都有专属运镜：黑边收拢、字幕浮现、镜头沿预设轨迹移动。这些不是随机特效，而是按角色写死的演出——谁死了，镜头就该怎么走，这一点在开发时就定死了。

美术与剧情是一体编排的：环境色调、道具造型、字幕断句都围绕同一套情绪设计。这样玩家在探索时看到的不是"又一个维度"，而是"他们走过的第五个地方"。

怎么用

无前置，装进 mods。建议：

  • 单人完整玩一遍再上服务器，否则会错过很多演出
  • 服务器可以关掉部分运镜（配置项），避免多人同时触发时画面混乱
  • 如果装了光影，某些维度的天空盒需要单独适配

取舍与边界

不做随机地牢。所有关键场景都是手工摆的，重复游玩价值不高，但第一次的体验是完整的。

不做强制任务 UI。没有任务列表、没有指引箭头，线索藏在对话和环境里。这提高了理解门槛，也保住了叙事感。

演出优先于系统。为了让运镜稳定，部分逻辑写成了"状态机 + 时间轴"，代价是后期改剧情要动代码，不能只改数据。

版本与依赖

当前 1.0.0。NeoForge 1.21.1 / Java 21，无前置，MIT 协议。维度与结构使用原版注册机制，存档可迁移；卸载模组后维度内容不会损坏，但相关进度会失效。

叙事节奏与多人环境

主线的推进不靠时间，靠玩家行为。相遇、同行、告别三个阶段各自有触发条件，触发之后演出才开始。这样做的代价是节奏不可控：有的玩家两小时走完，有的玩家卡在第一段好几天。

多人服务器需要考虑同步问题。运镜是按玩家单独播放的，四个人同时触发会各看各的，不会互相干扰；但如果服务器开了全局时间/天气同步，某些依赖环境的演出会变得不自然。建议在配置里关掉环境依赖，改用固定条件触发。

存档与兼容

维度与结构走原版注册，存档可以跨版本迁移。卸载模组后维度内容不会损坏（区块还在），但相关进度、对话状态会失效，重新装上也无法恢复——这些状态存在自定义数据里，没有做兼容层。

美术与演出是这套模组最重的部分，也是它最难被"轻量化"的原因。如果你只想要维度探索、不想要剧情，可以在配置里关掉对话与运镜，保留地形与生物。

为什么不做随机地牢

随机生成的地牢可以无限产出内容，但很难承载叙事：你无法在一个每次都不一样的房间里安排一段固定的告别。这套模组的所有关键场景都是手工布置的，重复游玩价值有限，换来的是第一次进入时的确定感。

如果你更看重可重复性，可以在配置里关掉剧情触发，只保留维度地形与生物，当作一个普通维度模组使用。
