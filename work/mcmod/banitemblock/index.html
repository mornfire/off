BanItemBlock

NeoForge 1.21.1 服务端 · 1.0.0

不想让某个方块或物品出现在服务器里，把名字写进配置就行。方块和物品分开列，互不影响。

不想让某个方块或物品出现在服务器里，把名字写进配置就行。

为什么做它

服务器运营里有一类需求很常见：某个方块太卡、某个物品破坏平衡、某个模组的方块会崩客户端。原版没有"禁用列表"，只能靠权限插件或者干脆删模组。删模组太重，权限插件管不到方块生成。

BanItemBlock 解决的就是这个缝隙：按配置全量清除指定的方块与物品。

它是怎么运作的

配置分两个文件，互不影响：

  • config/banitemblock-block.toml 管方块
  • config/banitemblock-item.toml 管物品

每个文件里是一串带命名空间的 ID，例如 minecraft:tnt、somemod:reactor_core。加载时模组会把这些 ID 解析成注册表项，然后在世界层面做清除：

  • 已经出现在世界里的方块会被替换掉
  • 玩家背包、容器里的物品会被移除
  • 新生成的（掉落、合成、交易）也会被拦截

因为是"全量清除"而不是"事件拦截"，所以即使方块是通过世界生成、结构、其他模组的逻辑放进去的，也一样会被处理。

怎么用

  1. 装服务端（客户端可选，装了能看到更一致的提示）
  2. 打开两个 TOML，把要禁的 ID 填进去
  3. /reload 或重启生效

建议先在小范围测试：禁掉一个方块，看看是否有模组的合成链、任务、成就依赖它。有些模组的进度会卡住，那不是 BanItemBlock 的问题，是配置需要调整。

取舍与边界

不做白名单。只支持禁用，不支持"只允许这些"。白名单会把整个注册表管起来，复杂度高得多，也更容易误伤。

不做权限区分。没有"管理员可以用"这种设定——如果允许例外，清除逻辑就会变得不可预测。

清除是不可逆的。配置里删掉的方块不会自己回来，改回去之后也需要重新生成。

版本与依赖

当前 1.0.0。NeoForge 1.21.1 服务端 / Java 21，无前置，MIT 协议。配置为纯文本 TOML，改完即时生效，不需要重启服务器（部分已加载区块需要重新进入才会反映）。

部署经验

最常见的坑是清理旧世界。配置改完之后，服务器启动并不会立刻把已生成的区块全部扫一遍——只有玩家进入、区块加载时才会处理。如果服务器已经跑了一段时间，建议：

  1. 先在测试存档验证配置，确认没有误伤
  2. 上线后观察日志里的清理数量，确认符合预期
  3. 让玩家重新进入常去的区域，触发旧区块清理

第二个坑是合成链断裂。禁掉一个中间产物，可能会导致某条合成链永远无法完成，玩家的进度卡在那里。上线前建议把配方表过一遍，看看被禁的物品是不是某条链的必经节点。

第三个坑是玩家背包里的存量。已经存在的物品会被移除，如果玩家刚买/刚合成，可能会觉得"东西凭空消失"。建议提前公告，或者用替换而不是清除（本模组只做清除，替换需要用其他工具）。

回滚

把配置里的 ID 删掉、重载即可恢复生成，但已经被清除的方块与物品不会回来。方块需要重新生成（旧区块不会自动补），物品需要重新获取。这是"全量清除"的代价，也是它比"事件拦截"更彻底的原因。

和其他管控模组的区别

权限插件管的是"谁能用"，这个模组管的是"世界上有没有"。两者互补，不冲突。如果同一个物品两边都禁，权限插件先拦玩家操作，配置层再把残留清掉，效果更彻底。

需要注意的是，部分模组会在启动时把物品塞进创造模式物品栏，如果只是从注册表移除而不清理物品栏，创造模式里仍然能看到图标。当前版本会连同物品栏一起处理。
