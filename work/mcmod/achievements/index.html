Mornfrost Achievements

NeoForge 1.21.1 · Fabric 1.21.1 / 1.21.11 · Forge 1.20.1 · 5.1.0

三百多条成就，正经的和不正经的都有。想给服务器找点事做的时候，它挺合适；一个人慢慢清也能玩上一阵。

三百多条成就，正经的和不正经的都有。

为什么做它

原版成就的密度太低了。一个服务器开上两周，玩家就会把能拿的成就全部拿完，之后上线只剩下打卡。真正让人留下来的往往不是奖励，而是"还有一件事没做完"这种感觉。

这个模组最初是给自己服务器写的：把日常玩法里那些值得被记录下来的瞬间——第一次下矿、第一次在末地迷路、第一次把朋友从岩浆里捞出来——做成成就。后来发现单人玩也挺有意思，就顺手多写了几百条，把网络梗、冷知识、奇怪的死法也塞了进去。

它是怎么运作的

全部成就都走原版成就系统的数据格式，不新增任何界面和依赖，所以加载顺序、兼容性、性能开销都很轻。三百多条成就被分成若干分支：

  • 探索类：维度、生物群系、结构、地形
  • 战斗类：击杀、生存、极限操作
  • 建造与收集类：数量积累、特定组合
  • 模组交互类：和常见模组内容联动的隐藏成就

成就之间存在前后依赖，前面的是"引子"，后面的是"目标"。这样玩家在列表里看到的是一条条线索，而不是一个平铺的清单。

怎么用

丢进 mods 文件夹即可，单人、服务器通用。服务器端装了以后所有玩家都会看到同一套成就，进度按玩家各自记录。如果是大型服务器，建议先把成就列表过一遍，关掉那些需要特定地图或特定模组才能拿的条目——否则列表里会出现永远灰着的成就，反而劝退。

多平台版本（NeoForge 1.21.1、Fabric 1.21.1 / 1.21.11、Forge 1.20.1）共用同一套成就定义，只有构建脚本和少量 API 适配不同。不要混装：同一个游戏目录里只放一个平台的构建。

取舍与边界

成就的作用是提供方向感，不是提供玩法。所以这个模组刻意不做奖励商店、不做成就点数、不做排行榜——那些东西会把"记录"变成"任务"，一旦有任务，玩家就会开始刷。

另一个取舍是不做强制引导。成就列表本来就是给人翻的，弹窗提示多了会烦人；当前版本只在获得时弹出原版的提示条。

版本与依赖

当前 5.1.0。NeoForge 1.21.1 / Fabric 1.21.1 / 1.21.11 / Forge 1.20.1，无前置依赖，MIT 协议。三套构建的成就内容保持一致，如果某个平台的原版 API 缺少对应事件，会在该平台降级为"只在获得时检查"，不影响其他平台。

在服务器上的实际表现

这套成就上线后最先感受到变化的不是玩家，而是管理员。以前服务器每周要发一次"本周活跃"公告，靠手动统计在线时长；现在一部分活跃度可以从成就完成率上看出来——哪条成就被大量完成，说明玩家在往那个方向玩，运营就可以顺着加大投入。

另一个变化是新玩家的第一个小时。原版前期的目标很稀薄，新手进服常常不知道干什么。成就列表在这里起到了路标作用：先做"第一次下矿"，再做"第一次合成铁镐"，一条条往下走，节奏自然就出来了。

需要提醒的是成就数量不要一次放太多。三百多条如果同时出现在列表里，新玩家会直接放弃阅读。比较合适的做法是先开放几十条主线，其余的按版本分批解锁——这也是为什么模组把成就分成了若干分支，服主可以按需关闭。

数据与兼容

成就进度存在玩家自己的存档里，跟着角色走，换服务器不会带走。跨平台构建共用同一套成就 ID，所以如果玩家在不同平台的服务器之间切换，同一条成就的判定条件是一致的，但进度各自独立。

和其他成就扩展模组共存时，注意不要在同一个存档里反复装卸——成就是按 ID 注册的，卸载再装会让已完成记录变成"找不到对应成就"的孤立数据，虽然不会崩，但列表里会出现空白条目。
