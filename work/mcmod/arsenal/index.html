Arsenal

NeoForge 1.21.1 · 1.0.0

中式、日式、西式的兵器被放在同一张工作台上：六种矿物、二十九类武器、七十二件护甲，从挖矿到锻造一条线走完。

把中式、日式、西式的兵器放在同一张工作台上。

为什么做它

做武器扩展最容易掉进的坑是"堆数量"：加几十把换皮的剑，数值改一改，看起来内容很多，实际玩起来没有区别。Arsenal 想做的是另一种东西——用一条完整的生产链把不同文化体系的兵器串起来，让"拿到一把好武器"变成一个需要规划的过程。

它是怎么运作的

规模上，它包含：

  • 6 种新矿物，从低阶到高阶分布在不同的挖掘层级
  • 29 类武器，中式、日式、西式各成一系，共 174 件
  • 72 件层级护甲，与矿物等级对应
  • 完整的矿物—武器—护甲合成体系

三系兵器的差异不只在造型：中式偏重劈砍与蓄力，日式偏重速度与连段，西式偏重穿刺与距离。同一个矿物等级下，三系的数值曲线不同，玩家需要按自己的打法选路线，而不是单纯比大小。

武器数据通过 DataComponent 持久存储，不是写死在物品 NBT 里的字符串。这样做的好处是：数值可以在 /reload 时热调整，服务器可以按需改平衡；同时组件结构稳定，跨版本升级时不容易丢数据。

怎么用

无前置，直接装。开局按原版节奏挖矿即可，新矿物会在对应层级生成。合成链比较长，建议先看一遍合成表再决定主攻哪一系。

服务器使用建议：

  • 高阶矿物如果生成率太低，可以在世界生成配置里调，不必改模组
  • 数值平衡用 /reload 热调，改完让玩家重进一次
  • 如果和别的武器模组共存，注意同名矿物的 ID 冲突

取舍与边界

不做随机词条。武器强度由矿物等级和类别决定，不 roll 属性。这样玩家可以精确规划，也避免了"刷到完美词条"的长期消耗。

不做无限升级。每件武器有明确的终点，强化到顶就是顶，不会出现"越玩越强、最后没有对手"的曲线。

合成链偏长。这是刻意的：如果一把顶级剑三步就能做出来，中间的矿物和中间产物就没有存在意义。

版本与依赖

当前 1.0.0。NeoForge 1.21.1 / Java 21，无前置，MIT 协议。依赖原版数据组件与 reload 监听，不修改世界生成以外的原版内容，卸载后已合成的物品会保留但失去热更新能力。

三系兵器的定位

三系不是简单的换皮，数值曲线明显不同：

  • 中式：单次伤害高、攻速慢，蓄力类武器多，适合正面硬拼
  • 日式：攻速快、连段顺，单次伤害偏低，适合走位和补刀
  • 西式：穿刺与距离见长，长柄武器多，适合控场

护甲跟着矿物等级走。低阶矿物做的护甲只提供基础防护，高阶矿物会附带抗性或其他被动。因为护甲和武器共用同一套矿物，玩家在前期就要决定主攻哪条线——资源是有限的。

在整合包里的调整方式

服务器或整合包通常需要改三件事：矿物生成率、合成配方、武器数值。前两个在世界生成配置和配方 JSON 里，第三个通过 DataComponent 在 /reload 时热更新。

如果同时装了其他武器模组，最需要注意的是矿物 ID 冲突。两个模组都注册 copper 之类的通用名字时，后加载的会覆盖前一个，表现是"某些矿石挖出来变成另一个模组的物品"。装之前先看一眼注册表，或者干脆只保留一套矿物体系。

材料与掉落的衔接

三系兵器共用同一套矿物，但掉落来源做了区分：低阶矿物在地表与浅层就能找到，高阶矿物集中在深层与特定生物群系。这让"换系"不是零成本——你已经投入的矿物路线不会白费，但改路线需要重新下矿。

如果整合包调低了矿物生成率，建议同步调整合成配方，否则会出现"武器做不出来"的真空期。配方是数据驱动的，改 JSON 即可。
