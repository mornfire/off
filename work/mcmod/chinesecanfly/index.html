中国人能飞

NeoForge 1.21.1 · 1.0.0

游戏语言是中文就能飞，切回英文马上掉下来。一个纯粹为了好玩写的模组，没想到还挺多人喜欢。

游戏语言是中文就能飞，切回英文马上掉下来。

为什么做它

这是个纯粹为了好玩写的模组。起因是一句玩笑：既然中文玩家这么多，为什么不能"语言特权"一下？于是就有了这条规则——只要游戏语言是中文，玩家就能像创造模式一样飞行。

它是怎么运作的

判断依据是客户端当前选择的语言，覆盖四种：

  • 简体中文（zh_cn）
  • 繁体中文（zh_tw）
  • 繁体中文（香港，zh_hk）
  • 文言文（lzh）

实现上分两侧：

客户端每 tick 轮询当前语言。语言属于上表且玩家不是创造/旁观时，向服务端发送 request_flight；语言切走的同一 tick 内本地立即停飞，并发送 revoke_flight。

服务端收到请求后设置 abilities.mayfly = true 并同步给客户端，符合原版的反作弊校验。服务端每 tick 会给已授权玩家补发飞行，所以死亡重生、切换模式之后会自动恢复。创造/旁观模式的玩家完全不介入，不会被误收回飞行。

怎么用

单人游戏（内置服务端）直接生效：进世界后打开语言设置选简体中文，双击空格起飞；切成 English 立刻掉下来，再切回中文又能飞。

多人服务器需要客户端与服务端都安装。纯客户端装是没用的——原版飞行校验在服务端，客户端绕不过去。

取舍与边界

不做白名单。没有"某些玩家不能飞"的配置，因为那会让这个玩笑变成权限系统。

不做隐藏。飞行状态是原版的 mayfly，其他模组和反作弊看到的就是"这个玩家有飞行权限"，不搞特殊标记。

语言切换是唯一开关。没有指令、没有快捷键，也不打算加——加了就不纯粹了。

版本与依赖

当前 1.0.0。NeoForge 1.21.1 / Java 21，无前置，MIT 协议。语言检测走原版 LanguageManager，不修改语言文件，所以和其他本地化模组兼容。

多人环境下的表现

服务端授权是这个模组的关键设计。客户端只负责"请求"，真正的飞行权限由服务端写入 abilities.mayfly 并同步，所以：

  • 原版反作弊不会误判（它看到的是合法的飞行权限）
  • 玩家切换维度、死亡重生后，服务端会补发权限
  • 创造/旁观模式的玩家不会被介入，也不会被误收回

如果服务器装了别的权限模组，可能会覆盖 mayfly 字段。表现为"语言是中文但飞不起来"，排查时先看权限模组是否在登录时重置了 abilities。

语言包的边界

判断依据是客户端当前选择的语言，不是系统语言，也不看游戏内文本。所以：

  • 装了中文语言包但选择英文 → 不能飞
  • 选择文言文（lzh）→ 能飞
  • 服务器强制语言（部分服务端模组会做）→ 以客户端实际选择为准

如果某个语言代码不在列表里（比如某些社区自制语言），按"不在列表内"处理，不授予飞行。想扩展的话需要改代码，不是配置项。

为什么不做成指令

模组上线后被问得最多的两个问题是"能不能加个开关键"和"能不能做成权限"。答案都是不加，原因不是懒，而是这个模组的全部趣味就在于"语言即开关"这一条规则。一旦可以手动开关，它就从"玩笑"变成了"另一个飞行权限插件"，而飞行权限插件已经有很多了。

如果你确实需要给部分玩家关闭，最省事的办法是配合其他权限模组在登录时重置 abilities，而不是改这个模组。

为什么只做四种语言

列表里只有简体、繁体（台湾）、繁体（香港）和文言文，看起来很少，但这四种覆盖了中文玩家的绝大多数客户端设置。其他中文变体（比如某些整合包自定义的语言键）不在列表内，是因为无法确定它们的语义边界——一个叫"中文"的自定义键可能是简体，也可能是混合。

宁可漏掉少数，也不要把不属于中文的语言误判进来，否则会出现"用英文也能飞"的荒诞情况。
