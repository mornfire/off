作品 / 模组

SQDCLib

NeoForge 1.21.1 · 前置库 · 3.0.1

写叙事模组时反复要的那几件事：状态存档、任务推进、对话分支、演出播放。抽出来做成前置库，四个模块互不依赖，只用一两个也行。

叙事向模组的公共前置库。

为什么做它

写叙事模组时，总有一些活是重复的：状态怎么存、任务怎么推进、对话怎么分支、演出怎么播。每开一个新项目都重写一遍，写到最后每个模组都长出一套自己的半成品框架，彼此还不能复用。

SQDCLib 把这四件事抽出来做成前置库，四个模块彼此解耦，用一两个也行。

它是怎么运作的

四个模块：

  • 状态存档：把叙事状态写进玩家/世界数据，支持版本迁移
  • 任务推进：任务节点的定义、前置条件、完成判定
  • 对话分支：对话树、选项、条件跳转
  • 演出播控：时间轴、镜头、字幕、事件回调

设计上有三条硬约束：

  1. 无第三方内容模组依赖：全部基于 NeoForge 官方 API，不要求安装任何内容模组
  2. 模块解耦：只用"对话"就不需要引入"任务"的代码路径
  3. 软依赖可选：GeckoLib 是可选软依赖，只有用到 animation 事件时才需要；没装时相关事件安全空转，不会抛 NoClassDefFoundError，也不会让演出中断

怎么用

把 jar 放进 libs/，在 neoforge.mods.toml 里声明依赖：

[[dependencies.your_mod]]
modId="sqdclib"
type="required"
versionRange="[1.0.0,)"
ordering="AFTER"
side="BOTH"

然后按需调用模块 API。文档在仓库的 README 里，示例代码跟着每个模块走。

取舍与边界

不做编辑器。没有可视化剧情编辑器，所有内容写在代码/数据文件里。这提高了上手门槛，但避免了"编辑器生成的格式没人看得懂"的问题。

不做运行时脚本。没有内嵌 JS/Lua，逻辑就是 Java。性能可控，调试也简单。

API 稳定性优先于功能量。新增模块会尽量不破坏旧接口，宁可多一个适配层。

版本与依赖

当前 3.0.1。NeoForge 1.21.1 / Java 21，无强制前置，GeckoLib 可选，MIT 协议。3.0 重构了状态存储与时间轴；如果你从 2.x 升级，需要按迁移说明改调用点。

接入方式与版本策略

依赖声明建议写最低可用版本，而不是精确版本：

versionRange="[3.0.0,)"

这样小版本更新不会导致依赖校验失败。库本身的兼容策略是：补丁版本只修 bug，次版本可能加 API，主版本才允许破坏性改动。

模块化带来的一个实际好处是构建体积。只用对话模块的项目，不会把任务与演出的代码路径带上——虽然对运行时影响不大，但对"这个模组依赖了什么"这件事更清晰。

设计边界

不做运行时脚本、不做可视化编辑器、不做热重载剧情。这三件事都会让库变重，而叙事模组的迭代速度通常没那么快，用代码写反而更可控。

如果之后要支持视频过场，会以可选模块的形式加入，不改变现有 API；同时会保证"没装对应依赖时安全降级"，这是这套库最重要的一条约束。

适合什么样的项目

如果你在做"有对话、有演出、有状态推进"的模组，这套库能省掉大量重复代码；如果只是加几个物品方块，用不上它。

它的目标用户是"一个人写叙事模组"的开发者——没有团队分工，没有现成的剧情工具链，需要一套能自己掌控、能改、能调试的基础设施。这也是它坚持"不做编辑器、不做脚本"的原因。

调试建议

接入这套库的项目，建议在开发期打开详细日志：状态读写、任务节点推进、对话分支选择、演出时间轴都会打点。叙事类 bug 往往不是崩溃，而是"状态没推进"，靠日志定位比断点调试快。

发布版记得关掉详细日志，避免刷屏。
